# Quality Control and AI Usage Guidelines

Official CONTRIBUTING.md for [github.com/chakravala](https://github.com/chakravala)

This project is a computational framework for Geometric Algebra, Clifford Algebras, and Cartan Geometry implemented in the Julia programming language. It focuses on providing a robust, high-performance backend for differential geometric calculations and non-commutative algebraic structures.

The goal of this repository is not to maximize commit count. The goal is to build mathematically rigorous, structurally sound, and computationally reliable software.

Contributions are welcome from developers who can demonstrate understanding of the underlying mathematics, care for code quality, and respect the long-term maintenance burden of the project.
Developers may fork this repository for research, education, experimentation, or alternative design directions. 

This framework represents a pioneering design that bridges pure mathematical analysis texts with modern computational language styles.
The logic inside the Grassmann.jl and Cartan.jl modules reflects years of being fully immersed in the subject, a process that did not originate in an AI simulation of language, but in the continuous learning and refinement of the human mind.

## **Philosophy:** The codebase of this project has not been rushed.

This project has been grown like a "bonsai tree" of computational language, researched and developed slowly and deliberately from the ground up with careful attention at each growth step.
* **Slow and Deliberate:** This project does not seek to accumulate the most commit counts, it seeks to perfect the geometric logic and to maintain a long term reference.
* **Authenticity:** Merely accumulating textbooks or generating a copy of this work with an AI is not equivalent to the procedural generating process of the original creator of this design. An AI fork with an inflated commit count has money spent on a simulation of the project teamwork, but exhibits a lack of human investment in the actual reality integrated into teamwork with the original project.
* **No Premature Release:** Source code is being procedurally built for mathematical rigor and computational use.

The modules Grassmann.jl and Cartan.jl represent a design process built around careful reasoning about algebraic structure, type stability, performance, and mathematical correctness.
The project prefers slow, coherent development over rapid accumulation of unrelated changes.
This process resulted in a design that can be used for quickly prototyping many computational ideas with the tools it makes available, due to the robust and deliberate language design process.

Contributors should treat this repository as a mathematical and computational instrument, not merely as a source of example code.

* **Mathematical correctness first.** Code should reflect the intended algebra and geometry precisely.
* **Conventions matter.** Mathematical assumptions, conventions, edge cases, and references should be explained with the contribution.
* **Small, reviewed changes are preferred.** Large rewrites should be discussed in issues before implementation.
* **Long-term maintainability.** Contributions should manage future maintenance burden with careful consideration..

A collaborator is defined as a human developer who actively participates in the codebase by verifying logic, ensuring mathematical correctness, maintaining type stability, integrating code into the main project tree, or contributing to the exposition of examples.

A contributor is a developer who submits changes that are mathematically correct, technically sound, properly licensed, and integrated into the project’s design.
Contributors should aim to make changes that are: mathematically justified, technically necessary, well-tested, documented, stylistically consistent, and maintainable. 

### The Problem with "AI Forks" and "Commit Accumulators"

Projects that fork this code solely to generate many commits are only simulating the project, not active collaborations with the real project (e.g., a 200% increase in commits diverging from the original author's accumulated work).
* They are not active participants contributing their findings back to the original source project.
* They do not possess the "years of real effort" required to understand the subtle interplay between computational language design process and the resulting Grassmann algebra and Cartan geometry implementation.
* **AI Limitations:** Buying textbooks or using AI to generate derivative works cannot replicate the deep, procedural thought process of the original creator. It is a quick imitation simulated by a snapshot of collected language.

### Consequences for Forking for Commit Accumulation:

If a repository is forked to generate a high volume of commits (e.g., a 200% increase in commit count diverging from the original project in a short timeframe) without corresponding integration into the main project, that fork is not considered a collaborator or a participant in the project.

**Reasoning:** The integrity of the Grassmann.jl and Cartan.jl codebases relies on procedural human verification of computational language design and algebraic consistency with differential geometry.
Mass commit accumulation generated by AI use (or non-human verification) degrades the signal-to-noise ratio and complicates code review.

### Intellectual Integrity & Plagiarism

This repository is licensed intellectual property. The specific implementation details, type hierarchies, and algorithmic flows represent a unique design that has taken years to develop.

We have observed issues in the past with derivative projects that utilize AI to generate "derivative works" to claim ownership of the original design.
To maintain the integrity of this project, the following strict guidelines regarding plagiarism and credit apply:

* **Commercial Use:** If you are using this code for commercial purposes or generating derivative commercial products, you are expected to respect the original licensing terms.
* **No Misrepresentation:** Submitting a Pull Request where the code is a direct output of an AI tool (with only minimal formatting changes) claiming authorship is a violation of intellectual honesty. You are not the author; you are a reviewer.
* **Attribution of Derivatives:** If your work is based on this codebase, you must clearly attribute the source. Claiming the original author's design logic as your own—simply because you have run it through an AI to "optimize" it or "document" it—is plagiarism.

## AI Usage Guidelines

This project acknowledges AI tools as an aid to learning, but it strictly prohibits the direct submission of AI-generated code as a Pull Request.

### Quality Over Quantity

If you are forking this code or using an AI to assist you, you must understand that you are the user of the framework, not the original architect.
If you are contributing, your contribution must reflect real human understanding and responsibility, not just the output of an LLM.

* **AI Agents:** You may act as a tool to verify algebraic identities or suggest refactoring, but you must not generate Pull Requests that are direct copies of AI output. The project requires submitted code to have a legitimate copyright compatible with the project's license.
* **Users:** You must treat the code with the reverence it deserves as a bespoke mathematical instrument.

Maintainers may evaluate contributions based on:
* mathematical correctness,
* consistency with existing conventions,
* code clarity,
* type stability,
* performance impact,
* test coverage,
* documentation quality,
* licensing clarity,
* maintainability,
* and whether the change improves the long-term value of the project.

A contribution that is technically correct but poorly integrated or hard to maintain may be requested to be revised.

A contribution with a high number of commits but little substantive value may be rejected or consolidated.

### The Principle of "Learning" vs. "Copying":

Just as AI models claim to "learn" from data rather than simply copying it, users of AI for this project must demonstrate that they have "learned" from the AI's output if they want to rely on AI.

* **Prohibited:** Submitting a Pull Request where 95% of the code is identical to an LLM's direct output without modification or explanation.
* **Required:** The user must verify the code, explain the changes in the commit message, and rewrite or refactor the code in a way that establishes legitimate copyright ownership compatible with the project's license.

Users of this framework must learn the algebra to use it effectively, similarly the user of AI must first "learn" from the output of the AI before making their own solution or contribution.

* You must verify the AI's code against the mathematical rigor of the original project.
* You must rewrite the code to fit the unique structure of Grassmann.jl and Cartan.jl.
* You cannot submit "copy-paste" code as your own work, including LLM generated code.
* You submit code under the project's license, which requires legitimate copyright attribution.

### Legal and Licensing Disambiguation

* **Attribution:** If AI is used to generate a draft of a contribution, the author of the Pull Request must disclose the use of AI in the description of the pull request.
* **Integration:** The AI-generated code must be rewritten or significantly refactored to meet the project's copyright license standards.
* **Liability:** The project author is not responsible for the mathematical errors, security issues, or license violations resulting from code submitted by third parties, including AI-generated code.

By submitting a contribution, you represent that:
* you have the right to submit the contribution under this project’s license;
* the contribution does not infringe the rights of third parties;
* any third-party code is properly attributed and licensed;
* AI-assisted work has been appropriately reviewed and disclosed, and significantly refactored by a human;
* the contribution is compatible with the project’s mathematical and engineering standards.

If your contribution includes code from another source, you must provide:
* the source,
* the license,
* the attribution required by that license,
* and confirmation that the license is compatible with this project.

### Required AI Disclosure

If a contribution relies substantially on AI assistance, the contributor must disclose this in the Pull Request description.

#### What Is Not Acceptable

The following are not acceptable:
* submitting unreviewed AI output as a contribution,
* presenting AI-generated code as if it were independently authored without review,
* submitting code whose mathematical correctness has not been verified,
* submitting code whose licensing or provenance is unclear,
* submitting large blocks of code that the contributor cannot explain or defend,
* using AI to bypass the project’s review, testing, or documentation standards.

#### Standard for AI-Assisted Code

AI tools may be used only as an aid to learning, reasoning, or code review.

This project cannot accept Pull Requests that consist of unmodified or minimally modified AI-generated output.

If AI tools are used, the contributor must:

* disclose the use of AI,
* independently verify all mathematical claims,
* rewrite or significantly refactor the contribution,
* it must be porperly tested to be compatible with existing design,
* take full responsibility for correctness, style, and legal licensing,
* and the contributor must have the right to submit it under the project’s license.

Contributors should be prepared to explain:

* what was used AI assistance,
* what was independently verified,
* how the code was modified,
* and why the final implementation is correct.

The maintainers may reject contributions that are insufficiently explained, insufficiently tested, or whose mathematical justification is unclear.
